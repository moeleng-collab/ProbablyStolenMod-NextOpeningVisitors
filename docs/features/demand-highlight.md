# 顾客需求与治安盘查高亮

- 当前状态：武器与订单相关配件高亮候选已安装；实际边框显示等待游戏内复验
- 目标游戏：《Probably Stolen》`0.46D`

## 行为规格

### 触发与颜色

- 当前收购顾客使用 `IsClientBuyingThisItem(item, true)` 判断直接需求；适用顾客意图为 `BUY` 或 `SELLNBUY`。
- 当前顾客意图为 `GUNSMITH` 且存在普通定制订单时，高亮带 `ADV_GUN_TAG` 的可定制基础武器；固定口径要求不匹配时不显示需求框。火力、精度等可通过改造提升的属性不作为基础武器排除条件。维修服务订单不标出无关的玩家武器。
- 定制与改造订单都会读取必选和奖励要求，高亮带 `WEAPON_MOD_TAG` 且符合至少一项属性方向的配件。火力、风格、可靠性、后坐、人机和精度同时检查百分比与固定值加成；提高属性要求只接受正向贡献，降低属性要求只接受负向贡献。尺寸增大要求接受武器配件，消音要求按简易／正规消音器等级筛选；口径要求不把配件误标为可修改口径。
- 每次刷新通过 `GunOrderData.ResolveOrderGun()` 读取当前订单武器，并用原生 `GunOrderRequirement.IsMet()` 跳过已经达成的条件。同一属性还有更高奖励档位未完成时继续高亮相关配件；所有相关条件达成后撤掉边框。未放置订单武器时按全部条件未完成处理。
- 当前顾客意图为 `INSPECTION` 时，只高亮按 `ContrabandHelper.InspectItem()` 同等只读标签规则判定会被检查的物品。
- 绿色：普通需求；黄色：赃物；红色：违禁品。
- 同一物品同时具有赃物与违禁品标签时红色优先。
- 外层容器继承所有可见子物品中的最高风险颜色：红 > 黄 > 绿 > 无。

高亮只新增不接收鼠标事件的边框，不移动物品、不成交、不执行随机盘查或结算。

### 库存范围与递归边界

需求模式扫描主库存、店面库存、柜台、展柜、集市、隐藏与已售库存，并递归未上锁容器。当前锁住的容器停止向内部递归，带 `ITEM_BEHIND_LOCK_TAG` 的物品不高亮。武器定制订单还会补扫已注册且可见的玩家自有物品，覆盖 3D 打印机等机器输出库存；该补扫只在武器订单模式启用，不改变普通收购和盘查范围。

盘查只扫描原版实际检查的根库存：

- 垃圾桶通过 `trashInvElement` 根节点扫描，桶内违禁品与嵌套容器按同一规则高亮；
- 懒惰治安官（`isLazyInspector`）跳过垃圾桶，与原版盘查范围一致；
- 隐藏库存仅在暗门打开时检查；
- 阻查容器及锁后、隐藏、锁定物品不暴露；
- `IsBlockSearchContainer()` 与隐藏边界停止递归；
- 合法物品不因盘查模式被高亮。

遍历有引用去重和 32 层深度上限。盘查标签判断不调用原版带 `Debug.Log` 的入口，避免每 0.25 秒重复写“发现物品”日志。

## 实现位置

| 文件 | 职责 |
| --- | --- |
| `src/DemandHighlightRules.cs` | 颜色分类、红／黄／绿优先级、递归边界与边框厚度 |
| `src/DemandHighlightUI.cs` | 根库存与物品树只读扫描、四边边框、低频宿主与清理 |

- `GameItemElement.Validate` Postfix：注册可见物品元素，不立即创建边框；
- `DemandHighlightHost.Update`：每约 0.25 秒读取当前客户、根库存和物品树，计算每个物品及父容器的最高风险；
- 顾客需求直接调用 `IsClientBuyingThisItem(item, true)`，避免在原版需求方法内部重复递归；
- 盘查使用原版同等的只读标签判断，绕开 `InspectItem()` 的日志调用；
- 边框由四个 `TreeNodeRender` 组成，挂在物品原生 `rotator` 与拖拽 `fakeRotator` 下，真实与拖拽层各一份，全部 `raycastTarget=false`；按 Q 旋转时边框随对应节点同步旋转；
- 边框厚度为 `max(1, gridSize / 16)`，不再使用原先较粗的 `gridSize / 12`；
- 无匹配、客户离开、物品销毁或禁用 Mod 时清除边框，正常刷新不逐次写日志。

该路径不得调用 `StartInspection()`、物品 `Destroy()`、交易或库存移动方法。高亮异常记录警告，原生物品交互继续。

测试本功能时须停用 `ClientDemandHighlight` 并重启，避免重复边框；不要修改第三方 Mod 文件。

## 验证与验收

当前全局自动化结果见[验证记录](../validation/current.md)。

### 纯规则覆盖

- 普通、赃物、违禁品与双标签颜色优先级；
- 父容器风险汇总；
- 锁后物品、锁定容器、盘查阻查容器和固定递归深度边界；
- 普通盘查包含垃圾桶、懒惰治安官跳过垃圾桶、需求模式不扫描垃圾桶；
- 引用去重及无匹配结果；
- 边框厚度随格子尺寸缩放，且最小为 1 个 UI 单位。

这些测试不实例化 Unity UI，也不验证真实物品树、旋转节点、拖拽层、客户生命周期或原版盘查完整流程。

### 游戏内专项验收

- [ ] 普通需求显示绿框，箱内匹配物品与外层容器正确显示，非需求物品无框。
- [ ] 赃物显示黄框，违禁品显示红框，双标签红色优先，嵌套容器继承最高风险。
- [ ] 普通盘查标出垃圾桶内的违禁品；懒惰治安官不显示垃圾桶高亮。
- [ ] 锁箱、锁后物品、隐藏及阻查容器不泄露内容，盘查不高亮合法物品。
- [ ] 移动、拖拽、开关容器、客户切换和物品销毁后边框位置与清理正确。
- [ ] 已摆放及拖拽中的物品按 Q 切换四个方向时，边框都完整贴合，调细后的厚度显示一致。
- [ ] 反复营业、读取存档和禁用重启用不积累边框或宿主。
- [ ] 高频刷新不产生重复盘查日志，不执行交易、盘查或物品移动。
- [ ] 定制订单只高亮口径合适的基础武器，维修订单不误标武器；机器输出口中的合适武器也能显示。
- [ ] 定制与改造订单按必选和奖励条件显示配件；安装配件或更换订单武器后，已达成条件动态撤框，更高未完成奖励档位仍保留提示。
- [ ] 常用分辨率和 UI 缩放下边框不遮挡关键交互。
