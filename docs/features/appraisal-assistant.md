# 放大镜自动鉴定与物品详情

- 当前状态：库存香烟的原生独立鉴定窗口已由用户确认可见；其他品类与完整交互待验收
- 目标游戏：《Probably Stolen》`0.46D`

## 自动填入真实估值

鉴定物品经 `InspectionUIManager.OnInspectItem()` 打开后，只有同时满足以下条件才自动填值：

- 当前客户意图为 `APPRAISAL_SERVICE`；
- 物品带 `APPRAISAL_ITEM`；
- `AppraisalHelper.GetCorrectBaseValue(item)` 返回正整数真实估值。

填值使用 `SetTextWithoutNotify()` 写入原生输入框，随后调用原生 `OnValueChanged()` 同步 `APPRAISAL_DEFAULT_VALUE`，防止下一帧用旧估值覆盖。不得调用 `OnAppraisalServiceEstimated()`，不自动提交、结算或销毁物品。读取失败、异常、非正值或不适用的客户／物品保留原输入。

## 真伪、价值与品质详情

同一次放大镜打开操作还会按物品类型显示只读详情：

- 免疫宁注射器、海明威香烟、食品券：直接显示正品／赝品；赝品逐项列出不合格原因。过期和已空按实际原因描述，不虚构为印刷造假。
- 肋明治：显示真伪及赝品原因，并显示真实价值和价值组成；开封及赝品使用原版固定价值。
- 仿生机械手、等离子燃料匣：显示真实总价，以及基础值、材质／接口／磨损／组件或品牌组合等适用加减项和最低价值。
- 荧光莓：直接显示正常、较小、发霉、未熟、干枯；未知字段组合显示未知，不强行归类。

价值拆解由纯规则计算，并与 `AppraisalHelper.GetCorrectBaseValue()` 的原版结果核对。字段缺失、未知枚举或拆解与原版结果不一致时，只显示真实总价和“详情不可用”，不猜测组成。界面只读取 `modifiedState` 与原生辅助方法，不修改物品标签。

物品详情与改造人检测使用独立面板。详情由七类 `Handle*` 原生物品处理方法的 Postfix 创建，避免其他 Mod 跳过 `OnInspectItem` 总入口后缀时丢失详情。物品详情采用与 `AppraisalAssistant 1.0.7` 相同的游戏原生窗口体系：通过 `CustomUIManager.Window(..., "overlay")` 创建可拖动独立窗口，使用 `CustomUIBuilder.AddLabel()` 添加文本，根据文本 preferred size 和窗口布局调整高度，并由 `FontLoader` 按中文、日文及其他语言设置原生字体。不再向鉴定面板注入自行创建的 `TreeNodeRender`、`Image` 或文本对象。切换物品会重建窗口，`InspectionUIManager.CloseUI` 和禁用 Mod 会关闭窗口，避免残留或串用。诊断日志记录物品 ID、文本及渲染字符数、窗口存活和可见状态、尺寸与字体。用户已确认库存香烟的原生独立窗口实际可见；其他物品、文本内容和完整交互仍需游戏内复验。

## 荧光莓鉴定后品质标志

`InspectionUIManager.HandleInsBerry` 完成后，按物品 `uniqueId` 记录本次查看时的品质；只有实际查看过的物品才显示标志，同种但未查看的其他荧光莓不受影响。重复查看同一物品会更新记录，字段不完整或品质未知时不写入猜测结果。

物品格右上角使用原生 `TreeNodeRender` 绘制小型彩色符号：红叉为发霉、紫叹号为干瘪、黄减号为普通、绿加号为小果。未熟没有第五种需求图标，继续只显示详情文本，不借用其他品质标志。标志尺寸随 `UISettings.current.gridSize` 缩放，并在用户确认位置正确的初版尺寸上增加 2 个 UI 像素；真实物品与拖拽预览各有一份，全部 `raycastTarget=false`，空物品格、调试物品和禁用 Mod 后不显示。

鉴定记录通过 `PlayerStore.ModData()` 的 `nextopeningvisitors.berry_appraisal.v1` 键随存档保存，不修改物品标签、价值、生成或交易规则。读档和新档事件会重新加载对应存档的数据，损坏记录只隐藏标志并记录警告。重新开启品质标志时会通过 `PlayerStore.FindAllItem(false)` 重新注册当前已有物品格，再应用已保存的鉴定结果，不要求重新鉴定。标志保存的是鉴定时的品质，后续状态变化须再次用放大镜查看才更新。

## 实现位置

| 文件 | 职责 |
| --- | --- |
| `src/AppraisalAssistantRules.cs` | 自动填值条件、三类价值公式、最低价值、肋明治赝品原因、荧光莓品质与标志映射 |
| `src/AppraisalItemDetails.cs` | 原版物品标签只读适配、真伪原因、原生价值对账与详情组装 |
| `src/AssistantAppraisalLocalization.cs` | 鉴定结果、价值行、原因、品质与窗口标题的 11 语文本；未知语言回退英文。这些表在 1.6.2 发布后于当前工作区补全，游戏内 11 语布局仍未验收 |
| `src/AppraisalAssistantUI.cs` | 自动填值、物品详情面板、鉴定记录入口与生命周期 |
| `src/BerryAppraisalState.cs` | 按唯一物品 ID 记录品质、确定性存档序列化与损坏数据拒绝 |
| `src/BerryQualityUI.cs` | 物品元素注册、存档加载、真实／拖拽标志绘制、低频刷新与清理 |

测试本功能时须停用 `AppraisalAssistant` 并重启，避免重复窗口或输入覆盖；不要修改第三方 Mod 文件。

## 验证与验收

当前全局自动化结果见[验证记录](../validation/current.md)。

### 纯规则覆盖

- 自动填值的适用条件与异常安全分支；
- 仿生机械手战术／豪华组合、等离子品牌组合及两类最低价值；
- 肋明治完整加成、开封固定价、赝品固定价和具体原因；
- 不完整或未知字段不生成猜测拆解；
- 荧光莓全部五种品质、四种请求标志及未知组合；
- 未鉴定不显示、唯一 ID 隔离、重复鉴定更新、存档往返、空数据和损坏数据拒绝；
- 全部鉴定与到店文案键（含窗口标题）在 11 种语言下非空，格式参数保留，未知语言回退英文；中文公式拆解。

这些测试不实例化 Unity 输入框或物品标志，不逐一执行原生物品估值函数，也不验证真实界面布局、存档文件或交易结算。

### 游戏内专项验收

- [ ] 真实估值自动填入且下一帧不恢复，仍需玩家手动确认才结算。
- [ ] 三类真伪物品的正品／赝品结论及具体不合格项与原生规则一致。
- [ ] 仿生机械手、肋明治、等离子燃料匣各项金额和总价与原版一致。
- [ ] 肋明治开封、赝品及多原因文本完整可读，不遮挡必要操作。
- [ ] 五种荧光莓品质与外观一致，未知组合不误报。
- [ ] 发霉、干瘪、普通和小果分别显示红叉、紫叹号、黄减号和绿加号；未鉴定及其他物品不显示。
- [ ] 移动、旋转、拖拽、开关容器及常用 UI 缩放下标志位置正确，不阻挡物品交互。
- [ ] 保存并重新读档后仅已鉴定物品恢复标志，两个存档互不污染。
- [ ] 连续鉴定不同物品时内容不串用，取消和重开界面无残留。
- [ ] 非鉴定客户、非鉴定物品和读取失败保持原输入。
- [ ] 禁用后不再自动填值、创建详情或显示品质标志，重启用无异常。
- [ ] 与第三方鉴定 Mod 隔离测试时无双份窗口或输入覆盖。
- [ ] 11 种语言下鉴定详情与标题布局无裁切或遮挡。
