# 开局特性：夜猫子

## 玩家行为

- 特性名称：**夜猫子**；英文为 **Night Owl**。
- 特性 ID：`nextopeningvisitors_night_owl`。
- 类型：正面开局特性；消耗 **2 点特性点数**。
- 选择该特性后，关店后的夜间外出不再受原版“每晚一次”的总次数限制。
- 同一个地点每晚只能成功前往一次；当晚再次选择该地点时，地图卡片不可选并显示提示，直接调用原生 `Travel()` 也会被拦截。
- 当晚访问过所有已发现地点后，店门不再补充外出次数。只打开地图后返回、没有实际前往地点，不消耗地点访问资格。
- 第二天按各地点原生 `lastVisitDay` 自动恢复，不额外清除地点事件、计数或其他状态。
- 未选择特性或 Mod 已禁用时，不增加外出次数，也不增加每地点一次的限制。
- 重伤、戒严、广场恐惧症休息期、夜间内容介绍状态及地点自身开放事件等原生或其他 Mod 的限制仍然有效。

## 第三方地点兼容

实现不列举原版地点，也不保存第三方地点白名单。每次打开店门或地图时，直接从 `AfterhourLocation.GetDiscovered()` 获取当前地点集合，并使用地点实例的 `Id` 和原生 `AfterhourLocationState` 判断。

因此，其他 Mod 只要通过原生 `AfterhourLocation.Register()` 注册地点，并沿用原生 `MapUIManager.Travel()` 到访流程，就自动获得相同规则，包括在本 Mod 之后注册的地点。绕过原生地点状态或完全自造旅行流程的 Mod 不在兼容保证内，仍需组合实测。

## 实现

| 位置 | 作用 |
| --- | --- |
| `NightOwlController.Register()` | 通过 `ModHelper.AddStartingPerk()` 注册 2 点正面特性及动态语言文本 |
| `StoreDoor.OnClick` 前缀 | 特性生效且当晚仍有未访问地点时，把耗尽的总次数补为 1，让原生店门检查继续执行 |
| `StoreDoor.GetTooltip` 后缀 | 次数耗尽时区分“仍可前往其他地点”和“今晚地点均已访问” |
| `MapUIManager.Travel` 前缀 | 按实际地点 ID、累计访问数和最后到访日拦截当晚重复旅行 |
| `TransitUI.BuildCard` 后缀 | 将当晚已访问地点的动态卡片标为不可用 |
| `TransitUI.Select` 前缀 | 阻止再次选中已访问地点并显示本地化提示 |
| `NightOwlRules` | 可脱离 Unity 测试的日期、地点及动态集合规则 |
| `NightOwlLocalization` | 特性名称、说明和提示的 11 语文本及英文回退 |

原生回店逻辑仍会把 `visitLeftTonight` 减回 0；本 Mod 不把它改成大数或永久锁定为 1。地点限制直接复用原生存档字段 `visits` 和 `lastVisitDay`，其中 `visits > 0` 用于避免把新地点的默认状态误判为已访问。无需新增 Mod 存档键。

禁用时通过 `ModHelper.RemoveStartingPerks("nextopeningvisitors")` 注销本 Mod 的开局特性，并立即停用规则判断。既有存档中的地点访问字段不被重写。

## 自动化覆盖

纯规则测试覆盖：2 点成本、稳定 ID、新地点默认状态、当晚重复、跨夜恢复、未选特性不干预、任意第三方地点 ID、所有地点访问完毕、空 ID、缺失地点集合，以及 11 语名称／说明／提示和英文回退。

编译与官方程序集扫描结果见[当前验证记录](../validation/current.md)。这些结果不证明真实 UI、存档或 Mod 组合已经验收。

## 游戏内验收

用户于 2026-11-20 对本次 1.7.0 功能反馈“测试没问题”。该反馈记录为“夜猫子”整体功能验收通过，但没有逐项场景清单；下列项目保留为详细回归参考，不据此声称第三方地点组合或其他既有功能已分别实测。

- [ ] 新开游戏时“夜猫子”显示为正面特性，消耗 2 点，名称和说明正确。
- [ ] 未选择特性时，原版每晚一次外出保持不变。
- [ ] 选择特性后，同一晚依次前往两个不同地点并成功返回。
- [ ] 第二次选择当晚去过的地点时卡片不可选、提示正确，直接旅行入口也不会绕过限制。
- [ ] 当晚只打开地图再返回，不影响任何地点的首次访问。
- [ ] 当晚访问所有已发现地点后，店门提示与不可继续外出的行为正确。
- [ ] 睡一觉后所有地点恢复；读档后当晚访问记录保持。
- [ ] 重伤、戒严、广场恐惧症休息期和地点关闭事件不被绕过。
- [ ] 与至少一个使用 `AfterhourLocation.Register()` 添加地点的 Mod 组合实测，新地点无需名单配置即可遵守相同规则。
- [ ] 禁用／重启后不再补次数或拦截地点，且无重复注册和日志异常。
