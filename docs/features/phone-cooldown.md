# 电话冷却清除与预约保护

- 当前状态：源码已实现；游戏内专项验收未执行
- 目标游戏：《Probably Stolen》`0.46D`

## 行为规格

按钮只处理四位供货商与奥丁，目标 ID 与[访客调度](visitor-scheduling.md#支持的联系人与-id)一致。`wanted4` 和其他联系人不属于清除范围。

补丁挂在 `PhoneUIManager.OpenUI()` 之后。按钮只应在号码显示文本为空且当前没有非本 Mod 发起的电话对话时显示。重复打开电话会销毁旧按钮再创建，避免积累实例和监听器。

点击后仅遍历五位目标联系人：

- 有待到访预约：跳过，保留冷却和预约；
- 无预约且处于 `Cooldown`：将 `currentCooldown` 设为 0，并将 `phoneState` 设为 `Regular`；
- 已就绪或字典中不存在：不修改；
- 非目标联系人：永不修改。

结果气泡显示清除数和跳过数；两者均为 0 时显示空状态。该批量操作不是事务，若游戏对象中途异常，已完成的联系人修改不会自动回滚。

## 实现位置

| 文件 | 职责 |
| --- | --- |
| `src/CooldownResetRules.cs` | 联系人目标、预约保护与冷却重置纯规则 |
| `src/PhoneCooldownResetButton.cs` | 按钮创建、可见性、真实状态写入和结果反馈 |
| `src/ModLocalization.cs` | 按钮、结果与失败文本及公共语言规范化 |

冷却与预约使用原版字段，不新增存档结构。既有按钮仍由游戏加载环境管理，完整禁用与重启用应按加载器要求重启，不能假设 Harmony 环境会即时撤销全部运行时修改。

## 验证与验收

当前全局自动化结果见[验证记录](../validation/current.md)。

### 纯规则覆盖

- 有待到访预约时跳过冷却，无预约目标可重置；
- 已就绪联系人和 Wild 等非目标不修改；
- 字典缺失、重复重置和幂等分支安全；
- 冷却按钮、结果与失败文本在 11 种语言下非空。

这些断言不验证真实按钮可见性、监听器积累或存档写入。

### 游戏内专项验收

- [ ] 仅在无号码、无其他电话对话时显示按钮。
- [ ] 重复打开电话不会出现重复按钮、重复监听或多次清除。
- [ ] 有预约的联系人保留冷却与预约，无预约且冷却中的目标被清除。
- [ ] 已就绪、非目标和 `wanted4` 不受影响。
- [ ] 清除数、跳过数和空状态反馈正确。
- [ ] 冷却修改保存并重载后符合对应存档。
