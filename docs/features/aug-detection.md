# 改造人检测、理由与到店身份提醒

- 当前状态：源码已实现；游戏内专项验收未执行
- 目标游戏：《Probably Stolen》`0.46D`

## 放大镜检测理由

进入放大镜模式时读取当前客户的 `isAug`、`augTier`、`augIdleTell` 和 `spriteName`：

- 非改造人显示未检出改造；
- 改造人显示检测确认，并依次报告明显机械头像、僵住、抽搐、四级异常；
- 明显头像根据 `spriteName` 识别，动作理由来自 `augIdleTell`，严重异常来自 `augTier == 4`；
- 均无可见线索时明确显示“身份由游戏判定确认，暂无可核实外观线索”，不得虚构扫描过程、头像或对话证据。

可见头像、动作特征与游戏身份判定必须分开表达。退出放大模式或禁用 Mod 时销毁提示，反复进入不得积累实例。

## 到店实时身份提醒

低频主线程宿主检查 `PlayerStore.isClientArrived` 和当前客户蓝图。改造体或通缉犯到店后立即在覆盖层显示提醒，无需使用放大镜：

- 显示顾客显示名及“改造体”“通缉犯”或双身份标题；
- 改造体显示改造等级；
- 通缉犯显示真名和举报奖励；
- 双身份同时显示两类信息，不互相覆盖；
- 普通顾客、无当前顾客或尚未到店时不显示，顾客离开后清理。

提醒只读取 `displayName`、`isAug`、`augTier`、`isWanted`、`realName` 和 `reportReward`。不修改客户状态，不自动举报、对峙、射击、派遣治安官或结算奖励，也不新增存档数据。到店提醒、物品鉴定详情和放大镜检测理由使用三个独立面板，避免相互销毁。

## 验证与验收

当前全局自动化结果见[验证记录](../validation/current.md)。

### 纯规则与本地化覆盖

- 非改造人、头像、僵住、抽搐、四级异常和没有可见线索的理由选择；
- 头像识别大小写与误匹配边界；
- 改造体、通缉犯、双身份、普通人和未到店状态的提醒条件；
- 七类检测文本及到店提醒入口在 11 种语言下非空，未知语言回退英文。

这些测试不验证真实客户蓝图、到店时序、头像渲染、动作可见性或 Unity 面板生命周期。

### 游戏内专项验收

- [ ] 普通人与改造人放大镜提示正确，理由符合实际。
- [ ] 改造体到店无需放大镜即显示等级，通缉犯显示真名和奖励。
- [ ] 双身份顾客同时显示全部字段，普通顾客不弹提醒。
- [ ] 顾客切换、离开、开关放大镜和鉴定物品时各面板互不干扰。
- [ ] 提醒不会自动举报、结算奖励或修改客户状态。
- [ ] 反复进出与禁用重启用不积累宿主或提示实例。
- [ ] 11 种语言在常用分辨率和 UI 缩放下无裁切或遮挡。
