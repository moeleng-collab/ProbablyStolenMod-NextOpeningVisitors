# 现有功能行为规格

- 适用版本：`1.5.0`
- 目标游戏：《Probably Stolen》`0.46D`
- 状态：描述当前源码已有行为；真实游戏内验收尚未执行

## 1. 目标与范围

本 Mod 调整指定供货商与奥丁的预约时序、开店队列顺序、电话冷却和电话文案，并提供交易案值预测、夜间调查预测及调查满值后的自动付费清除服务。

核心边界：

1. 不直接修改商品价格、特殊事件概率、普通顾客生成规则、罪案公式、判决阈值或普通盘查规则；
2. 预测只读，不代替真实交易或日结；
3. 自动清除只处理调查进度与案件状态，不清除案值、不撤销既有治安官或普通盘查；
4. 1.4.5 的访客优先、预约去重、待到访保护与 11 语支持继续保留。

## 2. 支持的联系人及访客 ID

| 联系人 | 普通预约 ID | 免费／首次预约 ID | 冷却清除 |
| --- | --- | --- | --- |
| Red Imp 供货商 | `courrierRedImp` | `courrierRedImpFree` | 支持 |
| Chem 供货商 | `courrierChem` | `courrierChemFree` | 支持 |
| Mining 供货商 | `courrierMining` | `courrierMiningFree` | 支持 |
| Pharma 供货商 | `courrierPharma` | `courrierPharmaFree` | 支持 |
| 奥丁 | `wanted4Normal` | 无 | 支持 |

`wanted4` 是剧情变体，不属于奥丁电话订单，不能被加速、去重、置顶或作为奥丁冷却保护依据。字符串匹配使用精确、区分大小写的 ID 比较。

## 3. 下一次开店到访与预约去重

游戏执行 `PlayerStore.HandleFutureClientQueue()` 时，Mod 在原版方法之前：

1. 按当前队列顺序扫描目标预约；
2. 普通与免费预约映射到同一联系人键，保留第一次出现的项目；
3. 同步删除后续重复项及其相同索引的延迟；
4. 将目标预约延迟统一为 `NextOpeningDelay = 1`。

原版随后继续处理预约队列。Mod 不直接创建新预约，非目标预约保持不变。两个平行队列长度不一致时拒绝猜测对应关系，由外层记录警告并保留原版流程。

原版方法结束后，若 `storeClientManager.clientStack` 可用，目标访客执行稳定置顶：目标之间及非目标之间均保持原相对顺序，不复制访客对象。

## 4. 一键清除电话冷却

补丁挂在 `PhoneUIManager.OpenUI()` 之后。按钮只应在号码显示文本为空且当前没有非本 Mod 发起的电话对话时显示。重复打开电话会销毁旧按钮再创建，避免积累实例和监听器。

点击后仅遍历五位目标联系人：

- 有待到访预约：跳过，保留冷却和预约；
- 无预约且处于 `Cooldown`：将 `currentCooldown` 设为 0，并将 `phoneState` 设为 `Regular`；
- 已就绪或字典中不存在：不修改；
- 非目标联系人：永不修改。

结果气泡显示清除数和跳过数；两者均为 0 时显示空状态。该批量操作不是事务，若游戏对象中途异常，已完成的联系人修改不会自动回滚。

## 5. 电话文案与语言

`LocHelper.GetLocalizedDialoguePhone()` 返回原版文本后，Mod 只改写已知的 21 个目标 key，统一表达“下一次开店”。未知 key 或缺少订单数量参数时保留原版返回值。

支持：`en`、`zh`、`ja`、`de`、`ru`、`fr`、`es`、`pl`、`ptBR`、`ko`、`it`。语言规范化忽略 `-` 与 `_`，中文区域代码归入 `zh`，葡萄牙语归入 `ptBR`，未知语言回退英文。

## 6. 交易案值／调查预测

### 6.1 显示与刷新

在玩家向当前客户出售物品的交易平板中新增两行：

```text
调查进度：80/100
案值：450 → 650（+200）
```

补丁在 `NegociationUIManager.Rebuild()` 前使旧注入失效，并在 `RefreshNow()` 后读取最新状态刷新。没有当前客户、罪案数据或可出售物品时隐藏新增区域，不保留额外高度。合法物品仍可显示 `+0`。原版信息区高度为 0 时会隐藏容器但保留旧 `sizeDelta`，Mod 此时按 0 捕获基础高度，确保反复放上、取下物品不会累计预测区域高度或移动文案。

预测覆盖当前 `GetSellableItem()` 返回的物品，以及其中未带 `ITEM_BEHIND_LOCK_TAG` 的子物品。物品价格、客户阵营、证据豁免、赃物／违禁品双标签与开局特长均从当前快照读取。

### 6.2 计算顺序

若客户 `isNoContributeToEvidence`，全部新增案值为 0。否则每个物品分别计算：

1. 赃物：协商成交价 × `STOLEN_VALUE_INT / 100`，按原版 `Math.Round` 顺序折算，再应用阵营和开局特长，计入 `FENCING`；
2. 违禁品：协商成交价依次应用阵营和开局特长，按类型计入毒品、武器、门禁卡或普通违禁品案值；
3. 同一物品同时具有两种属性时，两部分独立累加；
4. 汇总各罪名增量，显示当前总案值与成交后总案值。

阵营顺序为黑市除以 2、革命除以 3、下层且拥有 `LLTIGHTLIPS` 除以 2、卡特尔为 0。开局特长按 Intimidating 后 Blabbermouth 的顺序及原版取整规则处理。

调查行只显示真实 `evidenceLevel`。预测不调用 `CommitCrime()`、`CheckSoldContraband()` 或夜间调查结算，也不保证重新鉴定、交易锁定或其他 Mod 检查后一定成交。

## 7. 睡觉调查预测

### 7.1 显示与动态切换

日终平板新增三行：

```text
预计夜间案值：1000 → 780
预计调查变化：+6
次日调查进度：80 → 86/100
```

达到 100 时追加“将达到调查上限”警示并标红。`EndOfDayUIManager.InitUI()` 前使旧注入失效，`RefreshUI()` 后按最新服务勾选状态重算，因此切换夜间收尾人后使用新的 `isUsing`。

每次预测都从真实案值副本开始，反复切换不累计削减，不扣服务费、不写入案值、不生成夜间日志、不派遣治安官或保存游戏。

### 7.2 原版顺序与数值

```text
当前案值快照
  → 若勾选收尾人：按等级逐项削减
  → 若结算前调查 < 80：每项再衰减 20，最低 0
  → 按剩余总案值求基础调查增量
  → 应用声望／特长修正
  → 加到当前调查并截断到 100
```

| 收尾人等级 | 百分比部分 | 再固定减去 |
| --- | ---: | ---: |
| 1 | 当前值的 15%，按原版整数转换 | 50 |
| 2 | 当前值的 20%，按原版整数转换 | 150 |
| 3 | 当前值的 25%，按原版整数转换 | 400 |

| 收尾与衰减后的总案值 | 基础增量 |
| --- | ---: |
| 0～99 | +0 |
| 100～299 | +2 |
| 300～849 | +6 |
| 850～1199 | +9 |
| 1200～1499 | +12 |
| 1500～2499 | +20 |
| 2500 及以上 | +33 |

修正顺序：`SEC_TRUSTED` 整数除以 2；`SEC_PRIORITY` 乘 1.5，否则 `SEC_WATCHLIST` 乘 1.2；最后 `UL_PETITION` 乘 1.5。乘法采用与 `RNG.MultiplyAndRound()` 一致的 `Math.Round`。

预测仅覆盖本次收尾人与随后 `SecData.OnNewDay()` 的直接罪案结算，不预测随机盘查或其他 Mod 的额外修改。

## 8. 王哥自动证据清除

### 8.1 服务与触发

自定义服务 ID 为 `NEXT_OPENING_VISITORS_AUTO_EVIDENCE`，在王哥服务界面的 `Informant`（线人）栏目显示自动服务说明和下一次接受价格，与原版清除证据服务归入同一栏目。服务无额外解锁费、无 14 天冷却，也不提供界面直接购买动作；实际支付只发生在自动来电的接受分支。

在 `OnWakingUpLate` 对应的新日阶段，以及 `OnGameLoadedLate` 读档恢复时，同时满足以下条件时创建报价：

- `evidenceLevel >= 100`；
- 当天尚未生成过报价；
- 当前没有待处理报价；
- 当前服务价格有效。

每个游戏日最多创建一次。报价锁定当日与当时价格。持久宿主每 0.75 秒低频尝试展示，在晨间报告、交易、日终、地图外出、其他电话或其他模态 UI 占用时等待，不覆盖当前交互。

### 8.2 接受、拒绝与中断

来电正文分为三段连续对话，依次说明现状与风险、价格与处理内容、保留项与确认，避免长文本在单行气泡中被截断。分段遵循原版 `autoNextDialog` 设置：开启时自动继续，关闭时点击继续；接受／拒绝选项只出现在最后一段，不会自动选择。电话完整说明价格及“只清调查与案件状态，保留案值和已派遣治安官”。

接受前重新检查：有待处理报价、报价日期为当天、调查仍达到 100、价格大于 0、`playerCash` 足够。校验通过后：

1. 从 `playerCash` 扣除锁定报价；
2. 将 `evidenceLevel` 与 `secData.state` 设为 0；
3. 完成本次报价，阻止重复接受；
4. 下一价格更新为 `Math.Round(当前价格 × 1.2)`；
5. 保存报价状态并显示下一价格。

首次价格为 1000，序列从 `1000、1200、1440、1728……` 开始。只有成功接受才扣款和涨价；拒绝、余额不足、失效、异常均不涨价。价格溢出或无效时拒绝操作。本服务不消耗 `wildFavor`，与原版 `EVIDENCE_REMOVAL` 的 `+100` 价格曲线独立。

拒绝后当天不再自动生成，次日满足条件可再次来电，价格不变。余额不足保留待处理报价。未作选择关闭电话也保留报价；当天重新打开电话时可再次展示，读档恢复待处理报价时不重新定价。跨天旧报价失效，再按新日条件决定是否创建。

### 8.3 明确保留的原版状态

成功接受不得修改：

- `crimeAmount` 与 `crimeAmountTotal`；
- 未来访客队列中的 `securityOfficer`；
- 当前开店队列或当前访客中的治安官；
- 普通盘查安排；
- 原版手动证据清除服务价格。

不得调用 `ResetCrime()` 或移除对应治安官。若已派遣治安官之后到访，完全交给原版处理；调查降低后可能进入“证据消失”对话，因此本服务不是永久免于判决。

## 9. 数据、存档与禁用

1.4.5 的访客与冷却修改仍使用原版字段。1.5.0 另保存：

- 自定义服务当前价格：自定义 `NetworkUpgrade.cost`；
- 报价状态：`PlayerStore.ModData()["NextOpeningVisitors.AutoEvidence.State"]`；
- 状态 schema：`1|lastOfferDay|hasPendingOffer|offerPrice|offerDay`。

缺失状态按旧档默认值处理：无待处理报价、`lastOfferDay = -1`、价格 1000。无效状态回退安全默认值并记录警告，不主动修改现金或调查。状态随对应 `PlayerStore` 存档数据保存，不使用跨存档全局文件。

`OnDisable()` 退订新日／读档事件、销毁持久宿主、清除注入对话、注销自定义服务并清理预测 UI。禁用后的预测补丁只恢复布局，不再创建文本。完整禁用与重启用验收仍应重启游戏。

## 10. 异常与兼容边界

- 预测异常：隐藏新增区域并尽量恢复原版布局；
- 队列异常：记录警告，原版调度继续；
- 自动来电展示异常：不扣款、不清调查、不涨价，可低频重试；
- 接受异常：尝试回滚本次现金、调查、案件状态、服务价格与报价状态；
- 游戏更新或其他 Mod 修改同一方法、UI、罪案公式、电话状态时，必须重新验证；
- 扫描与纯规则通过不代表真实 UI、结算、存档和兼容组合已经验收。
