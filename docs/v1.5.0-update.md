# 1.5.0 需求更新：罪案风险预测与自动证据清除

- 基线版本：`1.4.5`
- 当前实现：`1.5.0`
- 目标游戏：《Probably Stolen》`0.46D`
- 文档状态：**功能已实现；纯规则、构建与官方扫描通过，游戏内验收未执行**
- 范围：三项新功能，不包含对 1.4.5 既有访客规则的改写

> 本文保留原始需求与验收标准。当前实际行为见[现有功能行为规格](behavior-spec.md)，源码映射见[技术手册](technical-manual.md)，自动化结果和未测清单见[测试说明](testing.md)。当前自动化结果为 818 条断言通过、官方扫描 160 个方法且 0 findings；这些结果不代表第 9 节的真实游戏内项目已经通过。

## 1. 更新目标

让玩家在承担罪案风险前看到可核对的依据，并在调查完成时获得一次有偿补救机会：

1. 交易前知道当前调查进度、当前案值和本次成交新增的案值；
2. 睡觉前知道当前服务选择会造成怎样的夜间调查变化；
3. 调查达到 100 后，可通过王哥自动来电选择是否付费清除调查。

本版本首先保证**预测与原版结算一致、操作不重复扣费、存档不错乱**，其次才是额外展示效果。

## 2. 术语

| 术语 | 对应游戏数据 | 含义 |
| --- | --- | --- |
| 案值 | `SecData.crimeAmount` | 各罪名当前仍有效的数值，总和影响夜间调查增量与判决 |
| 累计历史案值 | `SecData.crimeAmountTotal` | 历史累计值，不作为本版本“当前案值”的显示目标 |
| 调查进度 | `SecData.evidenceLevel` | 0～100 的调查值，不会因普通交易立即增加 |
| 案件状态 | `SecData.state` | 原版判决治安官派遣状态 |
| 夜间收尾人 | `WILD_FIXER` 服务 | 睡觉前按等级削减各项案值的服务 |
| 判决治安官 | `securityOfficer` 等 | 调查达到 100 且仍有案值时，由原版派遣的访客 |
| 普通盘查 | `securityInspector` 等 | 与判决上门不同的检查机制，本版本不修改 |

> 玩家文案中的“当天调查进度”按**当前存档的调查总进度**理解。它不是每天自动清零的独立数值。

## 3. 用户故事

### US-01：交易风险评估

作为玩家，我希望在确认交易前看到案值变化，以便判断是否值得出售赃物或违禁品。

### US-02：睡前动态评估

作为玩家，我希望在切换夜间收尾人时立即看到预测变化，以便决定是否为当晚购买该服务。

### US-03：调查完成后的补救

作为玩家，我希望调查达到 100 时接到王哥电话，可以按当前价格清除调查，避免因不知情而直接面对判决。

## 4. 功能一：交易界面实时预测

### 4.1 显示内容

在售卖／购买意图中由玩家向客户出售物品的交易界面，增加：

```text
调查进度：80/100
当前案值：450
本次新增案值：+200
成交后案值：650
```

可以将后三项合并为一行“案值：450 → 650（+200）”，但必须保留同等信息。

### 4.2 预测范围

- 当前单件出售；
- 当前可出售物品集合的批量出售；
- 客户预算不足、经原版确认后仍执行的批量出售；
- 同一物品同时具有赃物和违禁品属性时的两部分案值；
- 物品价格、客户阵营、客户证据豁免和开局特长对结果的影响。

预测表达的是：**“若当前可成交物品按当前条件成功出售，将新增多少案值。”** 若原版因重新鉴定、交易锁定或其他检查而没有成交，不得将预测说成已经实际增加。

### 4.3 计算规则

对每个预计成交物品，保持原版顺序：

1. 若客户 `isNoContributeToEvidence`，该物品新增案值为 0；
2. 若为赃物：
   - 取当前协商成交价；
   - 按 `STOLEN_VALUE_INT / 100` 折算；
   - 应用客户阵营修正；
   - 应用开局特长修正；
   - 计入 `FENCING` 预测增量；
3. 若为违禁品：
   - 取当前协商成交价；
   - 应用客户阵营修正；
   - 应用开局特长修正；
   - 按物品类型计入毒品、武器、门禁卡或普通违禁品案值；
4. 汇总全部物品与罪名；
5. 显示“当前总案值＋预测新增总案值”。

合法物品或无证据贡献的交易显示 `+0`，不能隐藏成无数据。

### 4.4 调查进度显示

交易成功只直接累计案值，**不直接调用夜间调查结算**。因此：

- 调查进度行显示当前真实 `evidenceLevel`；
- 交易前后的案值行实时变化；
- 不得在没有实际夜间结算时自行增加调查进度；
- 需要了解次日调查变化时，以睡觉界面预测为准。

### 4.5 实时刷新

以下情况必须重新计算：

- 打开交易界面；
- 切换选中物品；
- 添加、移除或成交物品；
- 协商价或其他价格特征变化；
- 客户、阵营、交易模式或证据规则变化；
- 从预算确认框返回或确认后刷新；
- 实际交易完成。

刷新只能读取游戏状态，不得调用 `CommitCrime()`、`CheckSoldContraband()` 或其他会写入案值的方法。

## 5. 功能二：睡觉界面动态调查预测

### 5.1 显示内容

在睡觉服务选择界面增加：

```text
预计夜间案值：1000 → 780
预计调查变化：+6
次日调查进度：80 → 86/100
```

达到 100 时使用明确警示，例如：

```text
次日调查进度：95 → 100/100（将达到调查上限）
```

### 5.2 动态要求

- 打开界面时立即生成预测；
- 每次切换“夜间收尾人”勾选后立即重算；
- 切换前后案值、调查增量、次日进度和达到 100 的警示必须同帧链路刷新；
- 反复切换不得累计削减预测案值，每次都从真实当前案值的副本重新计算；
- 其他影响预测的服务或特长状态发生变化时，也应使用最新快照；
- 预测不得扣除服务费、写入案值、生成夜间日志、派遣治安官或保存游戏。

### 5.3 原版顺序

预测必须模拟以下顺序：

```text
当前真实案值快照
  → 若勾选收尾人：按当前等级削减各项案值
  → 若当前调查进度 < 80：各项案值每日衰减 20
  → 按剩余总案值求基础调查增量
  → 应用声望／特长修正
  → 加到当前调查进度并截断到 100
```

### 5.4 收尾人规则

| 等级 | 每晚费用 | 每项案值先减去 | 再固定减去 |
| --- | ---: | ---: | ---: |
| 1 | 25 | 当前值的 15% | 50 |
| 2 | 45 | 当前值的 20% | 150 |
| 3 | 70 | 当前值的 25% | 400 |

百分比部分按原版整数转换顺序计算，每项最低为 0。预测只模拟案值效果，不扣除表中费用。

### 5.5 每日案值衰减

若**结算前的当前调查进度**小于 80，每种罪名分别减少 20，最低为 0。当前调查进度达到 80 后，不再执行这部分衰减。

### 5.6 基础调查增量

| 收尾与衰减后的总案值 | 基础增量 |
| --- | ---: |
| 0～99 | +0 |
| 100～299 | +2 |
| 300～849 | +6 |
| 850～1199 | +9 |
| 1200～1499 | +12 |
| 1500～2499 | +20 |
| 2500 及以上 | +33 |

### 5.7 修正顺序

1. `SEC_TRUSTED`：基础增量整数除以 2；
2. `SEC_PRIORITY`：乘以 1.5；
3. 若没有 `SEC_PRIORITY` 但有 `SEC_WATCHLIST`：乘以 1.2；
4. `UL_PETITION`：再乘以 1.5；
5. 乘法取整与原版 `RNG.MultiplyAndRound()` 一致；
6. 加到当前调查进度，最高显示 100。

### 5.8 预测边界

预测只覆盖本次 `EndNight()` 中收尾人与随后 `SecData.OnNewDay()` 的直接罪案结算。它不应伪造夜间日志，也不预测其他 Mod 在同一链路中额外做出的修改。若检测到其他 Mod 修改相同规则，需要在兼容性说明中标注预测可能失配。

## 6. 功能三：王哥自动电话清除调查

### 6.1 服务项

在王哥服务界面新增“自动证据清除”服务项，显示：

- 功能说明；
- 下一次接受清除所需价格；
- 调查达到 100 后会自动来电；
- 清除调查不会消除案值或撤回已经派遣的治安官。

本需求**不设置额外解锁费和 14 天冷却**。服务界面用于展示服务与当前价格，实际购买动作由自动电话中的接受选项完成，避免重复收费。

### 6.2 触发条件

同时满足：

- 当前为白天开始阶段；
- `evidenceLevel >= 100`；
- 当天尚未生成过本服务报价；
- 当前没有正在处理的相同来电。

原版 `SecData.OnNewDay()` 先完成调查结算后再判断是否来电。若玩家在接受前通过其他方式清除调查，来电应取消或在接受时提示无需处理，不得重复收费。

### 6.3 电话内容

电话明确显示：

- 当前调查已经满 100；
- 本次清除价格；
- 接受后只清除调查进度和案件状态；
- 案值和既有治安官安排不会撤销；
- 接受与拒绝选项。

余额不足时，接受选项不可用或返回明确提示，不得扣成负数。

### 6.4 接受结果

接受时重新核对当前调查、报价和余额，然后作为一个逻辑操作完成：

1. 扣除当前报价对应的现金；
2. `evidenceLevel = 0`；
3. `state = 0`；
4. 本次来电标记为已处理；
5. 下一次价格变为当前价格的 1.2 倍；
6. 显示成功与下次价格提示。

**必须保留：**

- `crimeAmount`；
- `crimeAmountTotal`；
- 未来访客队列中的 `securityOfficer`；
- 当前开店队列或当前访客中的治安官；
- 普通盘查安排。

不得调用 `ResetCrime()`，不得移除对应治安官队列项。

### 6.5 后续原版结果

如果已经派遣的治安官之后仍然到访，完全交给原版逻辑处理。按当前游戏版本：

- 当 `evidenceLevel < 95` 或总案值不大于 0 时，进入“证据消失”对话；
- 原版会降低 20 点治安声望、将 `state` 设为 0 并让访客离开；
- 如果到访时调查又达到判决条件，则由原版按当时案值选择罚款、监禁或处决分支。

本服务不得把“调查清零”宣传为“永久免于判决”。

### 6.6 价格

- 首次成功清除费用：1000；
- 每次**成功清除后**，下一价格 `= Round(当前价格 × 1.2)`；
- 取整规则与游戏 `RNG.MultiplyAndRound()` 一致；
- 初始序列：1000、1200、1440、1728……；
- 拒绝、余额不足、电话异常、调查已被其他方式清除：不涨价；
- 与原版 `EVIDENCE_REMOVAL` 每次增加 100 的价格曲线完全独立；
- 价格随对应存档保存，读档不得串用另一存档的价格。

### 6.7 每日一次与中断处理

- 每个游戏日最多自动生成一次报价；
- 拒绝后当天不再自动来电；次日若仍为 100，可以再次来电，价格不变；
- 未作选择直接关闭电话：保留待处理报价，可在当天重新接听，不重新生成报价；
- 保存并重载：待处理报价可恢复，但不得重复弹出多个电话；
- 成功接受是唯一能扣款和涨价的分支，重复点击不得再次执行；
- 跨天时未处理的旧报价失效，按当时条件决定是否生成新报价，旧报价本身不涨价。

### 6.8 支付范围

本服务使用玩家现金 `playerCash`，不消耗 `wildFavor`，避免与王哥服务界面购买其他升级的支付规则混淆。

## 7. 通用非功能需求

### 7.1 本地化

新增 UI、电话和结果提示支持现有 11 种语言；未知语言回退英文。中英文必须实际渲染验收，其他语言至少进行非空、参数和回退测试。

### 7.2 性能

- 不在每帧分配大型列表或重复创建 UI；
- 交易刷新可沿用原版刷新节流；
- 预测计算只处理当前交易物品和罪名列，不扫描无关场景对象；
- 反复打开界面不得累积监听器、GameObject 或协程。

### 7.3 失败回退

- 预测失败：隐藏预测或显示不可用，保留原版 UI 与交易；
- 服务注册失败：记录错误，不影响原版王哥服务；
- 自动电话失败：不扣款、不清调查、不涨价，保留原版日结；
- 禁用并重启：不再注入 UI、生成电话或执行清除。

### 7.4 存档兼容

- 1.4.5 旧档首次加载 1.5.0 时，价格从 1000 初始化；
- 新档与旧档行为一致；
- 每存档独立保存价格、报价日期和待处理状态；
- 读取历史存档时恢复该存档对应状态，不能使用其他存档或较新全局状态覆盖；
- 不修改原版罪案字段结构。

## 8. 不在本版本范围内

- 修改原版案值公式、调查区间或判决阈值；
- 撤销普通盘查或判决治安官；
- 清除案值、赃物标签或违禁品标签；
- 免除“证据消失”造成的治安声望变化；
- 预测普通盘查的随机搜索结果；
- 新增其他联系人或改变 1.4.5 的冷却清除目标；
- 修改商品价格、事件概率和访客生成规则。

## 9. 验收标准

### 9.1 交易预测

- [ ] 单件和批量预测与实际成交后案值逐项一致；
- [ ] 赃物与违禁品双重属性无漏算或重复算错；
- [ ] 阵营、证据豁免、价格和开局特长结果一致；
- [ ] 交易界面调查进度显示真实当前值；
- [ ] 交易完成及物品／价格变化后 UI 立即刷新；
- [ ] 仅打开或刷新界面不会改变任何存档字段。

### 9.2 睡觉预测

- [ ] 所有案值区间边界与特长组合通过规则测试；
- [ ] 收尾人三个等级与真实日结一致；
- [ ] 勾选或取消收尾人后所有预测字段立即更新；
- [ ] 连续切换不累积预测削减，不扣费、不写存档；
- [ ] 次日调查进度最高为 100，达到上限有警示；
- [ ] 预测结果与真实睡觉后的案值及调查进度一致。

### 9.3 自动电话

- [ ] 调查达到 100 的当天开始只生成一次报价；
- [ ] 接受、拒绝、余额不足、关闭、重载和跨天分支符合 6.7；
- [ ] 成功接受只扣款一次、只涨价一次；
- [ ] 接受后调查和 `state` 清零，案值与治安官队列保留；
- [ ] 已派遣治安官后续结果与原版一致；
- [ ] 价格序列、存档隔离、历史读档和旧档迁移正确；
- [ ] 原版手动清除服务的价格和行为不受影响。
